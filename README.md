## 登录 Grok Bot 时该选 Grok 还是 Cursor 账号？

客户端启动后会给你两个登录入口：Grok 和 Cursor。选哪个取决于你的权益挂在哪一侧。

官方对 Grok Bot 的说明是它沿用 Cursor 那套 SSO、鉴权和隐私模式，所以权益本来就在 Cursor 订阅里的，用 Cursor 账号登录最直接。也有教程写 Grok Bot 没有独立账号体系、本质是 Cursor 账号登录，再回头关联 Grok 或 X 账号。

另一种情况是权益从 X 订阅同步到了 Grok 账号。有一位订阅 X Premium+ 的作者记录过自己的流程：权益同步完成后，客户端识别到了资格，他选择用 Grok 登录，后续接 Grok 和 X 相关功能更顺。他自己在文中特别注明这是单人实测，不能推成所有 X Premium+ 账号都一定开放 Bot。

同时持有 Cursor 付费订阅和 SuperGrok 或 X Premium+ 的人，最常问的是额度会不会叠加。官方规则是不叠加，按周额度上限更高的那一档计算配额，不会把两份加在一起。The X Subscription 下 Grok、Cursor、Grok Bot 本来就在同一份订阅里，不需要再手动关联。

还有个容易卡住的环节：用 Grok 账号登录 Cursor 需要接短信验证码。有人反馈换到美国节点后 +86 号码能正常收码，也有人反复遇到"此手机号验证过多"、换节点也没用。客户端 v0.71.2（2026 年 10 月 14 日）对登录和账号关联流程做过简化，卡住的话先升级到这一版再试。

## 三端共用一个周额度池：额度是怎么被烧掉的

这是大多数介绍文章没讲、但对花钱最有影响的一段。

The X Subscription 下，Grok Bot、Grok、Cursor 三端共用同一个周额度池。官方原文写得很直白：Bot 的用量从这个席位的共享周额度池里扣，不是单独的、可叠加的池子。有些早期教程说"Bot 有独立额度，不占用 Grok 或 Cursor 的额度"，这个说法和官方文档对不上。

周额度每周固定重置，当周没用完的部分不结转到下周。

额度用完之后不会走月底后付费账单，而是实时从 Prepaid Credits（预付额度）里扣。需要在 grok.com/dashboard/billing 的 `Additional usage credits` 里提前充值，面板支持开启余额不足自动充值，也能设一个独立的月度额外消费封顶，避免自动充值失控。

在 Cursor 编辑器里调用非 Grok 系列的第三方模型，消耗不扣套餐内的 Grok 周额度，直接扣 Prepaid Credits。想在 Cursor 里用第三方模型，就得先保证预付额度里有余额。

Routine 定时任务是额度的隐形消耗大户。自 v0.75.2 起，官方把频率上限提到全账号所有 Bot 合计 300 次/小时、单条 Routine 最高 200 次/小时。不设限制地高频轮询，一周的额度可能几天就见底，而你根本没怎么手动用过。

升级后感觉"额度掉得比以前快"，多半就是这两个原因叠加：三端都在从同一个池子里抽水，后台还有一堆没人管的定时任务在跑。

**1. 支付走网页还是应用商店。** 通过 Apple App Store 或 Google Play 订阅的，切换套餐时不会自动取消，也拿不到退款，得自己到 iPhone 的「设置 > Apple ID > 订阅」或 Google Play 的「付款和订阅」里手动停掉，否则下个月两份一起扣。网页端直付的旧订阅在合并时会按剩余未使用天数比例退费。

**2. 试用资格对不对。** 12 个月内付过 Grok、SuperGrok、X Premium、Cursor 或 X Subscription 的任何一笔，都不符合邀请试用条件。
